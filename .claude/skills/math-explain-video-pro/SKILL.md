# 讲题视频 Pro

一道题 → 分镜 JSON → 带配音的动态讲解视频。**智力全在"解题复核 + 讲解设计 + 写分镜"**；
排版、配音、对时、渲染、合成全由脚本确定性完成，画面上每个点、每块重叠区域都是按真实数据算出来的。

必读：`references/lecture-design.md`（讲解设计卡：结构、直观手段、口播与板书规则）、
`references/storyboard-spec.md`（分镜 DSL）。样例：`examples/dongdian-chongdie.json`（动点问题，含全部常用几何写法）、
`examples/hanshu-duishu-sanjiao.json`（高中函数综合题，按参考答案讲：公式推导区、外层对数草图、五点法标准正弦/余弦图上看区间与升降、
单位圆证周期、诱导公式、存在/任意的取值条）、`examples/zhuchuan-fuli/`（初中物理选择题：珠串浸入水中，装置按真实数据逐帧算水深与示数、
实时读数、受力示意图、选项 C 的方法二；分镜由 `make_sb.py` 生成）、`examples/zhaoshuang-xiantu/`（初中几何综合题：赵爽弦图 → 图①②③
用形状变量一路变形过去，全等三角形绕中心转半圈重合，面积比的实时读数，第②问的方法二；分镜由 `make_sb.py` 生成）、
`examples/dianzu-wangluo/`（初中物理竞赛：电阻网络，上下翻转找等势、左右对折证可拆、真实电流点子流动、等效电路、方法二两式相减；
分镜由 `make_sb.py` 生成，电流用 numpy 解）、`examples/hanshu-yazhou/`（初中二次函数压轴题：正方形沿直线滑过抛物线，
先找“顶点落在抛物线上”的分段点、再逐段“横边取纵坐标、竖边代抛物线”列式，分段解方程的表格与检验，最后才用精确图像动态验证并推近看三个解；
交点、f 值都用 `world.funcs` 写成函数；分镜由 `make_sb.py` 生成）。
动配音相关（换音色、改停顿、改时间轴对时、接新 TTS）之前先读 `references/voice-lessons.md`（配音经验：用户听出过的
换音色/吞音/句中长停顿/字幕早于声音四类问题的根因与规矩，体检合格线）。

## 依赖

- `pip install dashscope imageio-ffmpeg playwright pillow`；渲染用本机 Chrome（Playwright `channel="chrome"`）。
- 字体随技能自带（`assets/fonts`：思源黑体、思源宋体、霞鹜文楷，均 OFL），公式用离线 KaTeX（`assets/katex`）。
- 配音（`scripts/tts_config.json`，分镜 `meta.tts` 可覆盖）：
  - **默认 Gemini 3.8 Flash TTS**（2026-09-28 用户 A/B 试听选定音色 Erinome；9-28 晚起**不加风格提示**，只用原版音色），
    经 OpenRouter 调用（`scripts/tts_gemini.py`，与白板专题课 engine 同一份）。
    **整片所有场景一次合成**（Gemini 每次请求嗓音会变，分场景合成会在换场景处"换人"），再按场景间真实静音切开；
    Gemini 不返回字级时间戳 → 用百炼 `paraformer-realtime-v2` 识别回来对时；**默认只合成一遍，没有明显问题就直接用**
    （对齐率 <90%、连续 ≥4 字读错、零碎可疑 ≥5 处、数字念错、音色突变（前后各 3 句中位音高差 >4.5 半音）才补合成，
    封顶 `gemini_takes` 遍；每处可疑先让第二个识别模型复核）。
    结尾模型多说的话自动截掉（`fix_tail`），句间念出的半个音自动静音（`stray_sounds.py`）。
    句间停顿按标点补到讲题节奏（句号约 0.9 秒）。所有插静音（补停顿、等动画）只插在波形里真正没声音的地方，切口 5ms 淡入淡出。
    只能用 OpenRouter 上的预置音色。某句反复读不清（如"右边的腰 PN"：中文字紧接字母），就改口播说法（"右边的 PN 这条腰"）。
    高中符号（sin、π/4、√2、x₁…）直接写，`narr_norm.hs_math` 转读法。成片响度全片同一个增益（不用动态 loudnorm）。
  - 出片后跑 `python scripts/audio_check.py <分镜.json>` 体检：插静音有没有切进字音（须为 0）、各场景中位音高是否一致。
  - 学科专项复听（tts 之后、render 之前）：几何题 `scripts/letter_check.py`（逐句比字母序列）；物理/化学题 `scripts/term_check.py 分镜 浸`
    （易误读字）；像英文单词的字母对 `term_check.py 分镜 --letters`。
  - 某处多念了（凭空多出的字母、词）：别整片重配，用 `scripts/cut_raw.py 分镜 起 止` 在静音处剪掉原始合成里那一段，再跑 `tts`
    （只重做后期、不花钱）；剪完再用第二个识别听一遍那一句（做法见 voice-lessons.md）。
  - 回退：`"engine": "bailian"` 用百炼 `qwen-audio-3.0-tts-plus` + 用户复刻音色（整段合成 + SSML 停顿，自带字级时间戳）。
  - **MAI-Voice-2.1（`"engine": "mai"`，2026-10-12 加）**：微软 MAI-Voice-2.1 经 OpenRouter（`microsoft/mai-voice-2.1`，音色
    `zh-CN-Mei:MAI-Voice-2.1`，中文另有 Bo / Lan / Wei / Grant / Harper），`scripts/tts_mai.py`。分镜 `meta.tts` 写 `{"engine": "mai"}` 启用
    （默认引擎仍是 Gemini）。**逐句合成**（voice 固定说话人，不像 Gemini 要整片一次合成）、自己补句间停顿、按波形估字时刻——
    **只要 OpenRouter Key，不要百炼 Key**。大写字母连写（ABCD）自动拆开读；每句合成结果缓存在 `~/.cache/explain-video-pro/mai/`，
    口播没改的句子不再花钱；配音缓存 `build_*/audio_mai/`。不返回时间戳，字时刻是估的（逗号停顿从波形找，段内按字权重均分），
    锚点动作误差一般 ≤0.15 秒；出片后听一遍锚点动作是否落在对的词上。第一次用要核对采样率（语速异常会在日志里提示，
    `mai_pcm_rate` / `mai_format: "mp3"` 可调）。`letter_check.py` / `term_check.py` 的第二识别用百炼，没有百炼 Key 时改用 OpenRouter 的识别模型人工抽查。
  - 两个引擎的配音缓存分开放（`build_*/audio_gemini/`、`build_*/audio/`），切换不互相覆盖。
  - Key 由用户自己写入，模型不经手：`~/.openrouter_api_key`（或 `OPENROUTER_API_KEY`）、`~/.dashscope_api_key`（或 `DASHSCOPE_API_KEY`，合成与识别对时都用）。

## 流程

### s0 · 备料与解题复核
1. 题目截图先转写成文字（**原文一字不改**），关键数字向用户确认。
2. **题目给了参考答案（docx/图里常附在题后），优先顺着答案的思路讲（方法一）**：先把答案拆成"步骤清单"（每步：用了什么公式/性质、
   得出什么式子），分镜照清单逐步讲、板书照答案的式子写；只把答案一笔带过的地方讲细。**有别的好方法，作为"方法二"补充**：
   方法一讲完后单开一小节，简短，不替换方法一（2026-09-30 用户："原题是给了答案的，这个要多做参考""在提供了答案的情况下
   优先顺着答案的思路讲解，当然如果你有其他方法可以作为方法二补充"）。没给答案才自己解，并用**第二种方法验算**，两法一致才往下走。
3. 写 `world` 前先用笔（或 Python）把所有关键坐标、分段时刻、面积算一遍：分镜里写的每个数（6 秒、3 cm、21）都必须与几何一致。

### s1 · 讲解设计（按 lecture-design.md 零~三节）
先过**两条铁律**：①顺着参考答案讲（方法一），别的好方法作"方法二"补充；②推理只用学生做得到的方法，配推理的图学生画得出
（基本函数标准图、单位圆、数轴、题目自带图），**电脑精准图用来做动态直观展示**（推完再"看见"：平移重合、动点看增减、区间搬家；
口播"用电脑画出来看一看"），不当推理依据（9-30 高中老师看片反馈："先把图像都画出来再看单调性，人根本画不出来，也不会这么判断"；
用户补充："电脑精准图是用来做动态直观展示的"）。
再给每一问填"卡点 / 直观抓手 / 关键定格 / 落地板书"四格；选直观手段（第三节表）。这一步决定视频好不好，别跳。

### s2 · 写分镜 `<题目>.json`（放在题目自己的文件夹）
先 world（点、图元、部件）→ 再 scenes 骨架（标题/读题/每问/想一想/总结）→ 最后逐节拍写口播和动作。
口播精炼：一句一事、画面先行、口播说为什么、板书写是什么。

### s3 · 闸门
```
python scripts/make_video.py <分镜.json> check
```
ERROR 清零，WARN 尽量清（长句拆开、板书缩短）。[INFO] 给出口播字数与估算时长。

### s4 · 排版预览（不花配音钱）
```
python scripts/make_video.py <分镜.json> preview --fake
```
按 4.3 字/秒估算时间轴，每个节拍的定格出一帧 + 四宫格拼图（`build_<名>/preview/_sheet_*.png`）。
**逐张看**：标签压线/互挤、文字出界、强调没对准、图形钻到板书下、板书折行、场景切换残影。改分镜再来。

### s5 · 配音
```
python scripts/make_video.py <分镜.json> tts
```
Gemini 是整片缓存：任何一个场景的口播改了，整片重配（7 分钟一遍约 ¥0.8）；只改画面、停顿规则不花钱。
之后再跑一次不带 `--fake` 的 preview 核对真实时序（字幕、锚点动作是否落在对的词上）。

### s6 · 渲染合成
```
python scripts/make_video.py <分镜.json> render
```
450 帧一段、每段一个子进程（Chrome 逐帧截图 + x264 编码，画面不变的帧自动复用），按空闲内存定并行路数；
看门狗：某段 75 秒没进度就杀掉重渲（最多 3 次），成片逐帧扫黑屏，最后拼接、混入配音。
（2026-09-30 以前是一个进程一大段死等：内存被别的程序吃到 4GB 时几路浏览器卡死，渲染挂了一个半小时，用户问"卡这一步很久了"才发现。）
4 分半的片子约 3~6 分钟出片。只改了画面（没改口播）→ 直接 render；改了口播 → 先 tts。

### s7 · 终检交付
- ffmpeg 抽几帧（每个场景中段）看最终画面；核对时长。
- 提醒用户亲自听一遍配音（音色、停顿、读法只有人耳能验收；读错的字在口播里改写法，如"PN"→"P N"）。

## 设计要点（为什么这样做）

- **版式（2026-09-24 用户定）**：浅色系——浅青灰桌面 + 白色方格纸、卡片化的板书/字幕/时间条（白卡 + 细青边 + 柔和投影），
  字体三件套：思源黑体（标题、界面、字幕）、思源宋体（题干）、霞鹜文楷（板书）；品牌青 #00B2B2 做编号块、标签、进度条。
  左上角放经纶学霸标志（**青色字浅底版**，高 100px，用户嫌大过、指定过这一版），片尾卡居中放大标志。深色主题 `meta.theme="dark"` 仅作备选。
- **结尾**：每片以 outro 片尾卡 + 一句结束语收尾，再缓缓淡出，不许戛然而止。

- **连续的世界**：题干下方的图和讲台上的图是同一个几何世界，切场景时图平滑搬家、镜头推拉，学生不会"换一张图就断片"。
- **动画自动等待**：节拍里某个动作比口播长（平移 7 秒），下一句自动等它做完再开口——所以写分镜只管"该动多久"，不用凑字数。
- **确定性渲染**：`runtime/engine.js` 的 `seek(t)` 是时间的纯函数，任意一帧可单独重渲，也能并行。
- **正确性闸门在前面**：点坐标由表达式算出、重叠区域逐帧裁剪、时间条读数来自同一个变量——画面不会和数学打架；
  口播里的数则靠 s0 的复核。

## 已知边界

- 世界里有平面图元（多边形/线段/角/尺寸/点/文字/区域交集）、函数图像（curve/axes/ticks）、参数曲线（pcurve：单位圆、转圈螺线，
  闭合可填色）、左对齐的大号公式（text `align:"left"`、`cls:"fmbig"/"fmbox"`）（2026-09-29/30 高中函数题加的，样例 `02_对数三角综合`）；
  物理装置用的 `world.funcs`（自带辅助函数解水深等）、实时读数（text `{#}` + `num`）、`world.clip` 画框裁剪（9-30 初中物理题加的，样例 `03_珠串浮力`）；
  立体图、统计图还没有图元类型（需要时优先扩展 `runtime/engine.js` 的图元，别在分镜里硬拼）。
- 复杂函数的精准图只做推理之后的动态直观展示，不当推理依据（见 lecture-design.md "两条铁律"）。
- clip 交集要求裁剪多边形是凸的（两凸多边形求交最稳）。
- 旧版"5星学霸母版"讲解视频仍用 `primary-math-explain-video`；本技能是独立的新版式。
