# 配音经验（2026-09-28 两轮试听 + 三轮返工总结）

用户对配音非常敏感，下面每一条都是用户**耳朵听出来**的问题，根因都是实测查出来的——而且全是我们这边
拼接、插静音、对时的做法造成的，不是模型本身。改配音相关代码前先读完这页。

## 一、选型

| | Gemini 3.8 Flash TTS（默认） | 百炼复刻音（回退 `engine: bailian`） |
|---|---|---|
| 语调起伏（基频半音标准差，真人老师 5.1） | Erinome 5.3 | 4.4 |
| 呼吸节奏 | 句中自然换气 | 一句一口气，句间统一停约 1.5 秒（"停顿和换气差点意思"） |
| 字级时间戳 | 不给 → 百炼识别对时 | 自带 |
| 音色 | 29 个预置音色（OpenRouter 不能复刻） | 用户复刻音 |

用户 A/B 试听选定 **Erinome**（试听页：`视频讲解 新版（pro）\配音试听\配音AB试听.html`）。
客观指标只作参考，拍板靠耳朵：新音色、新引擎一律先做 A/B 试听页让用户听。

**不加风格提示（9-28 晚白板课用户定，9-29 本技能跟着改）**：原来传"小学数学老师给学生讲题：亲切、清楚……"时模型在"表演"，
8 分钟整片里开头音高 224Hz、后面 180Hz（差近 4 个半音），相邻句明亮度忽高忽低，用户听出"前后声音不一致"。
现在 `tts_config.json` 的 `gemini_style` 为空，只用原版音色。

## 二、用户听出来的问题 → 根因 → 规矩

| 用户听到的 | 根因（实测） | 规矩（代码里已落实） |
|---|---|---|
| 1:20 前后"明显换音色" | 每个场景各请求一次合成，生成式 TTS 每次重新"挑"嗓音：9 段中位音高 175~234 Hz，1:19.5 正是换段处 | **整片口播一次请求合成**，再按场景之间的真实静音切开（`tts_gemini.synth_film`）。任何一段口播改了，整片重配 |
| 2:10、2:12 等多处"吞音、消音" | 插静音按识别时间戳下刀，69 段里 16 段切进了字音 | **插/删静音只在波形真正安静处**（`quiet_point` 取最长静音段中点；非插不可时取能量最低的气口），切口 5ms 淡出淡入 |
| 3:36"明显的停顿"（所以——1.5 秒——高 DF） | ① 量"原来已停多久"的代码恒为 0，每个句间都叠 0.9 秒；② 不加标记时 Gemini 句间只停 0.2~0.5 秒，和"所以……"的句中顿挫一样长，补的停顿插进了句中 | **每句后加 `<short pause>`**，让模型自己在句间停 1.0~1.6 秒（明显长于句中换气）；`quiet_run` 量原有停顿，只补不足、删超出（句号目标 0.9 秒，上限 1.15 秒） |
| （修上一条时暴露）字幕比声音早 1 秒多；句间拖到 1.7 秒 | 识别把停顿后第一个字报早，把停顿前最后一个字报进停顿里（时间轴以为这句没说完，又等 0.8 秒） | **按句界对照波形校正时间戳**：本句的字不早于停顿末，上句的字不晚于停顿头（`make_video.speech`） |
| 句间拖长 | 板书擦入、发光强调也让下一句等它做完 | **只有图形运动（tween）和镜头（camera）要让口播等**；show 最多等 0.4 秒；板书、划重点、强调、隐藏不等（`blocking_end`，作者可用 `wait` 强制） |

一句话：**生成式 TTS 不能分段请求拼长片；插静音、对时都不能只信识别时间戳，要看波形。**

## 三、合成质量把关

- **默认只合成一遍，没有明显问题就直接用**（用户 9-28 白板课："三遍太奢侈了"；`gemini_takes` 只是封顶遍数）。
  配音识别回文字与口播逐字比对，读偏、吞字、漏读记为可疑（`suspicious()`）；不算的：字母读法（D→地、PN→皮恩）、
  同音字（点→碘；整串带上下文注音）、两/二互换、地/的/得，相隔 ≤3 字的几处并成一处。
  每处可疑再让第二个识别模型（百炼 `qwen3-asr-flash`，关数字归一化）听一遍（`number_slips`）：听到原文就是识别听错、放过；
  涉及数字又没听到原文的算"数字念错"（硬伤）。**明显问题**才补合成：某场景对齐率 <90%、连续 ≥4 字多读/漏读/读错、
  零碎可疑 ≥5 处、数字念错（`obvious_problems`）。
- **音色突变也算明显问题**（2026-09-30 加，`tts_gemini.voice_jump`，判定线 `VOICE_JUMP = 4.5` 半音）：同一遍整片合成里，模型也会
  慢慢把嗓音压低、再突然跳回去——赵爽弦图那遍中间两分半压到 165Hz，换场景一下子跳到 210~239Hz、明亮度 +16%，就是用户说过的
  "突然两段音色有差别"。逐句量中位音高，前后各 3 句的中位之差超过 4.5 个半音就再合成（已交付几片最大 3.0~3.6）。
- **能自动修的不算明显问题**：全片结尾模型自己加的话（`make_video.fix_tail` 在口播末几个字后的静音处截断）、
  句间把 `<short pause>` 念出的半个音（`stray_sounds.clean` 静音掉，再用改过的原始合成重做后期，不重新花钱）。
  这套从白板专题课 engine 移植（2026-09-29），两边 `tts_gemini.py` 相同。
- **同一句三遍都读糊 = 写法问题**：中文字紧接字母容易糊（"右边的腰 PN"三遍都被读成"右边的一"）→ 字母放前面
  （"右边的 PN 这条腰"）。写口播时就避开：`字母 + 这条/这个 + 名词`。
- 选中那遍的原始合成（未切、未调停顿）存 `build_*/audio_gemini/_raw.pcm/_raw.json`：只改停顿、时间轴规则时复用，
  不重新合成（省钱，声音也不变）。`tts --force` 才会重合成。

- **物理/化学课另做一步易误读字复听**：`python scripts/term_check.py <分镜.json> 浸`（可列多个字）——每处切出前后一小段让
  第二个识别再听，读音相同就算对（"浸没"听成同音"进墨"算对，听成"侵/沁"才是念错，要人去听）。9-30 珠串浮力题 17 处全对。
- **几何题逐句字母复核**：`python scripts/letter_check.py <分镜.json>`——每句含字母的口播让第二个识别再听，比对字母序列
  （DGO 念成 DOG、MH 念成 MD 这类是硬伤；第一个识别对字母不稳，suspicious() 不查字母）。9-30 赵爽弦图 61 句全对。
- **模型会凭空多念字母**（9-30 赵爽弦图）：把"把 △BEO 绕点 O 转半圈"念成"把 A B C D 三角形 BEO……"。纯字母的多念
  suspicious() 不算（它跳过只有字母的差异），只有 `letter_check.py` 抓得到。**修法：别整片重配，剪掉**——
  先用第二个识别听几个递增的小段（148.9~150.2、~150.36、~150.56……）定出每个字母的起止，再在前后静音处
  `python scripts/cut_raw.py <分镜.json> <起> <止>`（改原始合成、自动备份），然后 `tts` 只重做后期、不花钱。
  第一刀可能没切干净（这次第一刀漏了 A，因为识别时间戳把"把"报晚了 0.3 秒），剪完一定再听一遍。
- **字母 R 会被识别成 二/儿/尔**（9-30 电阻网络题）："R零"被听成"二零"、"小r"被听成"小二"，对齐率掉到 89%、还被当成"数字念错"，
  封顶合成被白白耗掉。已改：`align.canon` 比对时把 R/二/儿/尔/两 归成一类（只用于比对，不改时刻）；`number_slips` 复核改成
  读音比对（`tts_gemini._sound_seq`：数字转读法、字母 R 念 er、′ 念撇、不带声调的拼音），"代进/带进"这类同音也放过，"7减3→7减4"照样抓。
- **模型会在同一处反复"加话"**：两遍都在总结里"小方格可以拆开。"后面自己加"好，这就是……""好家伙"，都在以字母开头的句子
  （"AC 和 CB 电压相同……"）前加"好"。以字母开头、或列举式总结的下一句，前面加个口语连接词（"这样一来，""再把……"），第三遍就没有了。
- **函数压轴题（9-30）配音的几条**：
  - 坐标读法要写死：`{A(−1,0)|A 负1 逗号 0}`。只写"负1，0"时，Gemini 这一遍说"逗"、下一遍说"逗号"、有时直接停顿，每遍都被判可疑。
  - 字母之间别用冒号：`Q 还没过 B：M 在下边` 被念成"过 C，B 在下边"（两个识别都这么听），改成两句"Q 还没到 B。M 在下边……"。
  - 同一句两遍都读错（`t 过了 (3−√17)/2` 两遍都念成"二分之负三加根号十七"）= 写法问题，改说法（"E 越过 J 以后……"），别再重合成碰运气。
  - 负数：识别器把"负二"写成"-2"，对齐时要把减号当"负"（字母、数字后面的减号当"减"），`align.word_stream` 已处理。
  - 场景对齐率按读音比（`tts_gemini._scene_rate`）：短标题句里两个同音字就能把字面对齐率压到 89%，误判成明显问题。
  - 结果：这片合成了 7 遍才定下来（约 ¥6），其中 4 遍是判定误报或写法问题造成的；判定改好后，后面的片子应该一两遍就够。
  - **杂音清理曾把真的字母静音掉**："0≤t≤1 时，Q 还没到 B。"里的 B 前后都有停顿，看上去是孤立的一小段响声；识别把它的
    时间戳报早了 0.2 秒，落在"已对上口播"的判定窗口外，就被当杂音静音了，成片变成"Q 还没到，M 在下边"。那次又没备份，只好重配。
    已改 `stray_sounds`：识别成口播里有的单个/两个字母的一律不静音（"Bye"这类多字母的照样清）；改原始合成前先存
    `_raw_before_clean.*`。跑完 `letter_check.py` 看有没有字母句对不上，对不上的换几个窗口再听（窗口越宽越容易被上下文带偏）。
  - 总结开头模型两遍都自己加"好/好的"（"……三个 t。好的，回顾一下"）：别重配，`cut_raw.py` 剪掉，剪完用第二个识别再听一遍。
- **"2t" 曾被读成"2吨"**（9-30 函数压轴题）：narr_norm 的单字母单位规则把数字后紧挨的 t 当成吨，"2t−4"变成"2吨负4"。
  已改成单字母单位必须和数字隔一个空格（"20 g""3 s"照旧读克、秒），紧挨着的是代数式。写口播前先打印一遍读法
  （`make_video.Board(分镜).scene_tts_text(场景)`）逐句看，这类错光看字幕发现不了。
- **单字动词可能念糊**："设外面每根也是 r"的"设"三遍被两个识别听成"说/手/受"（窄窗口再听也不是"设"）→ 改成"假如"。
- **口播里的圈号数字会被误判**：写"第①问"，Gemini 读"第一问"，但读音流里没把 ① 算成"一"，被判"数字念错"，
  白白封顶合成了三遍（其中两遍倒是真有问题：模型多念了一句、倒回去重复了一大段）。已在 `align.SYM` 把 ①~⑩ 映射成一~十。
  以后口播尽量直接写"第1问""最后一小问"。
- **几何题的字母对**：`python scripts/term_check.py <分镜.json> --letters`——ME、BE、HE、ON、AD、AH 这种两个大写字母正好拼成英文单词的，
  逐处让第二个识别再听，识别出大写字母就是按字母读的；小写单词或汉字才要人去听。9-30 试音：Gemini 连写的"ME""ON""AH=HE"
  都按字母读（与字母间加空格的写法时长一样），所以口播照常连写，不必加空格。
- 物理单位直接写在口播里（`1.5 N`、`600 Pa`、`10 N/kg`、`cm³`），`narr_norm` 读成牛、帕、牛每千克、立方厘米；
  9-30 修了两个老毛病：`cm²` 曾被读成"c平方米"（复合单位没按长度从长到短替换），单位后面紧跟汉字时不认（"1.6 N减"）。

## 四、每片必跑的体检：`python scripts/audio_check.py <分镜.json>`

| 项目 | 合格线 |
|---|---|
| 插入的静音切进字音 | 0 段 |
| 句子中间 >1.2 秒的停顿 | 0 处 |
| 句间停顿（不含换场景、等运动） | 中位约 0.9 秒，最长 ≤1.3 秒 |
| 字幕出现到开口 | ≈0 秒 |
| 相邻场景中位音高跳变 | ≤1.5 半音（开头问句偏高、结尾"再见"偏低属语调，可略超） |

响度：先量整片响度，再**全片乘同一个增益** + 限幅器压个别尖峰（`make_video.level_filter`，-16 LUFS / 峰值 -1.5 dB）。
别用单遍 `loudnorm`：它是动态模式，随时间调音量，白板课片子前后差到 2.5 分贝，用户听着"前后声音不一致"。

## 三点五、高中符号的读法（2026-09-29 高中函数题试音）

`narr_norm.hs_math` 只改配音文本，字幕照原样显示：`sin/cos` 写成 `sine/cosine` 给模型（老师读 [saɪn]，写 sin 怕被读成英文单词）；
`f(x)` → `f x`；`x₁` → `x一`；`π/4` → `4分之π`、`3π/2` → `2分之3π`；`√2/2` → `2分之根号2`；`−a/2` → `负2分之a`；
`∈ ∀ ∃ ∞ ∪ ·` → 属于/任意/存在/无穷/并/乘。试音两个识别模型都听到标准的 "sine x""四分之派""根号二"。
`align.py` 把 π、√、∞ 按读音（派、根号、无穷）进读音流，口播写 π、识别写"派"或"π"都能对上。
字幕里用 `−`（U+2212）、`₁₂` 下标、`√`、`π`，好看也不影响读法。

## 五、Gemini 3.8 Flash TTS 经 OpenRouter 的接口事实（2026-09 实测）

- `POST https://openrouter.ai/api/v1/audio/speech`，`model: google/gemini-3.8-flash-tts`，**只接受 `response_format: "pcm"`**
  （24kHz 单声道 16bit），`instructions` 可传风格提示（现在不传，见第一节），`voice` 用预置音色名；Key 读 `~/.openrouter_api_key`。
- 偶发 `Provider returned 400` 是上游临时错误，要重试（白板课踩过）；长片请求超时设 900 秒。
- 行内标记 `<short pause>`、`<long pause>` 有效且不会被读出来；long pause 实测 2.6~3.2 秒，太长，只给连写 `｜｜` 用。
- 不返回时间戳：用百炼 `paraformer-realtime-v2`（dashscope `Recognition`，16kHz wav，`language_hints` zh/en）识别对时，
  与口播对齐一般 95%~100%；建连偶发失败，要退避重试。
- 一次请求 1000 多字（约 4 分钟音频）稳定，约 2 分钟出音频；输入上限 8192 token、输出上限约 10 分钟音频。
- 价格 $9/百万音频 token（25 token/秒）：4 分钟一遍约 ¥0.45，2027-01-01 起翻倍。
- 音色复刻、音色设计只在 Google 官方接口（需要 Gemini API Key + 境外网络）。

## 六、以后换新 TTS 引擎，先测这五样

1. 一次合成几分钟长文本，音色稳不稳（逐段中位音高）；
2. 给不给字级时间戳（不给就接识别对时 + 波形校正）；
3. 句间停顿能不能控制（标记 / SSML），句间停顿能不能和句中顿挫区分开；
4. 字母、多音字、数字的读法；
5. 做 A/B 试听页让用户听，定了再接流水线；接完跑 `audio_check.py`。
